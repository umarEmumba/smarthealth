**1. [Rule 1 - Bug] Visit reconciler race test failed in a full-suite run**
- **Found during:** Task 3 regression (first full run: 8 failed, 1315 passed; 7 of the failures were the trace tests that need OTel, which the plan says to run separately)
- **Issue:** `tests/visit/test_visit_reconciler.py::test_a_pass_racing_the_workflow_step_finalizes_once` saw 3 audit entries instead of 1. Audit dedupe relies on the partial unique index `ix_audit_dedupe_key`; services create it only at start-up, and `tests/libs/test_audit_indexes.py` drops the whole shared `audit_log` collection (and so every index) when it finishes, so in a full run the index was gone before the visit tests ran. It reproduced 6 of 6 times in isolation once duplicates existed.
- **Fix:** `test_audit_indexes` now restores the indexes after its cleanup and the race test calls `ensure_audit_indexes` first. No assertion was changed or loosened.
- **Side effect handled:** the failing runs had written 14 duplicate `visit.billing_finalize_requested` documents (7 dedupe keys) into the dev `audit_log`; they made `ensure_audit_indexes` fail with `DuplicateKeyError`, which would also have crash-looped a service restart. I deleted exactly those 14 extra test-created documents (keeping the first of each key) and re-ensured the four indexes.
- **Files modified:** `tests/libs/test_audit_indexes.py`, `tests/visit/test_visit_reconciler.py`
- **Commit:** `186131e`
