# Phase 02.1 Plan 07: Booking Saga Reliability Summary

**BookingWorkflow now requests the confirmation notification only after confirm and re-offers a freed slot to the waitlist after a direct booking fails (both behind workflow.patched with old and new histories replaying), compensations and post-commit audits can no longer undo or misreport a committed booking, and past slots are rejected at the API and in the saga.**

## Accomplishments

- **Claims verified (as planned).** Reproduced in the code: S7 (`ACT_NOTIFY` ran before `ACT_CONFIRM`), S3 (a failed audit after confirm made the saga void a confirmed booking), S5 (nothing started the waitlist when a direct booker failed), S6 (`create_appointment` never compared the slot time).
- **S7 + S5, one workflow, two patches (Task 1).** `notify_after = workflow.patched(NOTIFY_AFTER_CONFIRM_PATCH_ID)` is evaluated once after billing; a pre-patch history replays notify then confirm, a new run confirms and then notifies through the same extracted `_notify_best_effort`. In the failure path, after `mark_failed`, `start_waitlist_advance` runs only when the hold was attempted, the reason is not a lost race, `workflow.info().parent is None` and `workflow.patched(BOOKING_FAILURE_WAITLIST_PATCH_ID)`. The conditions are evaluated cheapest first so the marker is recorded only when the branch is live.
- **Replay proof.** `test_replay_booking_patches.py` replays both v1 fixtures and both new p21 fixtures, asserts the markers, the activity order in the confirmed p21 history, one `WaitlistAdvanceWorkflow` child in the rejected p21 history, no sensitive text in any fixture, and that the same notify move WITHOUT the patch raises `NondeterminismError` against the v1 history. The p21 fixtures were recorded once through the gateway against the live stack with the opt-in recorder.
- **S3 guards (Task 2).** `void_billing` and `release_slot` read the appointment status first and return with `outcome=skipped_committed` for `AppointmentStatus.COMMITTED` (no Billing call, no audit). The audit after `confirm`, `cancel_appointment` and `swap_slot` is best effort. `confirm_booking` treats a retry on any COMMITTED status as success when the slot is still booked by the appointment.
- **S6 (Task 3).** API 422 `slot has already started` placed after the scope check and before the status check (replay still answered first, D-08); saga `validate` compares the slot start with the database `now()` and raises non-retryable `SlotInPast`.
- **Docs.** README (Known limitations rewritten), `docs/architecture.md` (sequence diagram and order note), `docs/architecture.html` (ASCII flow) and the dashboard (steps reordered, deviation callout rewritten) now describe the implemented order.
