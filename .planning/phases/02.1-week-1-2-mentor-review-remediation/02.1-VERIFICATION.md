## Per-item evidence (the 15 mentor items)

### M1: appointment state machine - VERIFIED
- `services/scheduling/domain/enums.py`: `AppointmentStatus` has `CHECKED_IN`, `COMPLETED`, `NO_SHOW`; `ACTIVE` lists every slot-holding status.
- `services/scheduling/migrations/versions/scheduling_0004_appointment_states.py` widens the status CHECK, `uq_appointments_active_slot` and the patient-overlap EXCLUDE to the new states (so even a raw UPDATE cannot free a checked-in slot); downgrade is lossy and documented.
- `appointment_repo.check_in_appointment`: row-locked, conditional `UPDATE ... WHERE status = 'confirmed'`, window judged with the database `now()` (`too_early` / `too_late`), one history row, idempotent repeat. `complete_appointment` requires `checked_in`. `mark_no_show` requires `confirmed` and `now() > slot_end + grace` on the DB clock.
- Cancel (`cancel_appointment`) and reschedule (`swap_slot`) act only on `confirmed`, so they cannot touch checked_in, completed or no_show. Refusal is enforced at the API (`api/appointments.py::_refuse_unchangeable`: 409 "appointment already checked in" / "already completed" / "was a no-show") and again inside the workflows: `CancelWorkflow` returns `failed` on `NotCancellable` before any billing call, so no refund is issued; `swap_slot` rejection releases the new hold and leaves the booking untouched. Every `UPDATE appointments` in the service is one of the guarded functions (grep).
- Visit side: `services/visit/api/visits.py::check_in` calls Scheduling's internal check-in first (`references.check_in_appointment`), maps window refusals to 409, fails closed with 503 when Scheduling is down, and a retry converges. `VisitCompletedWorkflow` has a patched fourth branch that completes the appointment.
- Tests: `test_appointment_states.py` and `test_check_in_scheduling_state.py` (65 passed); replay proof `test_replay_visit_completion.py`.

### M2: schedule-change propagation - VERIFIED
- Provider: `provider_repo.record_schedule_change` is flushed into the same transaction as the template update, template deactivate and provider deactivate (event table `schedule_change_events`, CHECK on `change_type`); a PATCH that changes no value writes no event; internal feed `GET /internal/schedule-changes` and `POST .../ack`.
- Scheduling: `ScheduleChangePollerWorkflow` (Temporal Schedule) -> `poll_schedule_changes` starts `ScheduleChangeWorkflow` under `schedule-change-{event_id}` with `start_once`, and acknowledges only after the start (at-least-once). `apply_schedule_change` works by set difference against the re-expanded current templates: withdraws stale `available` future slots (conditional `withdraw_slot`), flags the booking on stale `booked` slots (`flag_schedule_change`: `confirmed` or `checked_in`, set once, status and slot unchanged), inserts replacement slots, all in one transaction; ambiguity withdraws nothing (retryable upstream error vs non-retryable `ReferenceInvalid`). A second pass runs after the hold TTL through a durable timer. Cancel and reschedule of a flagged appointment withdraw the old slot instead of freeing it.
- Wiring: workflows and activities registered in `services/scheduling/worker.py`; Schedule registered in `schedules.py`.
- Tests: `test_schedule_change_feed.py`, `test_schedule_change.py`, `test_schedule_change_workflow.py`, `test_replay_schedule_change.py` (history `schedule_change_p21.json`): all pass.

### S3: failures after commit - VERIFIED

## Known open risks (from the SUMMARYs and README "Known limitations"; none blocks the goal)

1. **Audit entries after a committed step are best effort (S3).** If Mongo is down at that moment the audit entry is lost for good; the transition itself stays in `appointment_status_history`. Phase 3's transactional outbox is the general fix.
2. **Schedule changes and reconciliation are polled** (poller about every 15 s, reconcilers every 60 s), so a stale slot stays bookable for up to the poll interval; the saga's `validate` step catches an inactive provider.
3. **Schedule-change second-pass gap.** A slot still `held` after the hold TTL (reaper late) gets no third pass; it stays bookable until the next event or a re-run of the idempotent apply. A flagged appointment stays `confirmed` until staff act, and the flag stays on a cancelled one. Waiting waitlist entries of a deactivated provider are not cleaned up.
4. **Cancel and reschedule billing is still bounded** (`cancel_incomplete:billing_pending`, `reschedule_incomplete:billing_pending` for an operator); only visit billing retries open-endedly, so a visit workflow can stay open while Billing is down.
5. **Reconciler fairness.** Batch limits (50 and 100), oldest first, no per-row backoff.
6. **`no_show` is automated only**; visits created before Phase 2.1 settle their appointment as `not_checked_in` with no backfill.
7. **Refresh tokens are single-use** without family revocation: reuse is refused but does not kill the descendant chain; access tokens issued before the change carry no `rjti`; a Redis outage blocks refresh (503); legacy mixed-case emails are matched but not rewritten.
8. **Replay discipline:** the open-ended billing retry only changes activity options, so its `workflow.patched` marker is a convention, not something replay enforces.
9. **Pagination covers patients, providers and clinics only**; appointment lists have a `limit` but no `X-Total-Count`; the department list is unpaginated.
10. **NFRs are targets, not results.** The local single-instance stack is not claimed to meet NFR-01 or NFR-02; `sustained`, `burst` and `contention` k6 profiles were never run; the smoke profile crossed its thresholds twice (human item 2).
11. **Test and environment hygiene (read-only observations):** a leaked Temporal Schedule `test-aeebfdd1c4a6-reconciler` is still registered and unpaused on the live Temporal (task queue `scheduling-tq`, every minute, about 133 runs; idempotent, so harmless but noisy and a source of races with reconciler tests); `tests/libs/test_audit_indexes.py` still drops the shared dev `audit_log` collection; the live reconcilers share databases with the tests, so tests must seed fresh rows; the e2e visit flow depends on the clock (skips within 40 minutes of clinic-local midnight).
12. **Postman collection** (untracked) still describes the pre-rotation reusable refresh token.
13. **The traceability test is a mapping check, not a behavior check** (`tests/docs/test_phase21_traceability.py` keeps the item-to-test mapping and the docs from rotting; the behavior evidence is the test runs above).
