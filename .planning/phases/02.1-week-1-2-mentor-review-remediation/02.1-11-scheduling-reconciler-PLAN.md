<objective>
Scheduling-side half of S4 (stuck states) plus S5 for slots freed by the reaper, plus the no-show sweep that makes M1's `no_show` state reachable.

Claim verification (done while planning, reproducible):
- Pending appointments that block the slot: `uq_appointments_active_slot` covers `pending`; the hold reaper only fails a pending appointment when its slot is still `held` and expired. A booking workflow that is terminated, or that closes without writing a terminal state (for example the pending-starter finds the workflow already closed: `start_once` returns False and `mark_workflow_started` still sets the marker), leaves a pending appointment and an available slot that nobody can book. Real.
- Waitlist entries stuck in `matched`: `WaitlistAdvanceWorkflow` documents (module docstring) that a claim that committed just before `claim_failed`, or a resolve that exhausts its budget, leaves the entry `matched` "for an operator"; nothing ever revisits it. Real.
- Billing orphan after the reaper: `slot_repo.expire_holds` marks the appointment failed and frees the slot but never voids a billing record the dead saga had already verified. Real.
- Freed slot never re-offered: the reaper and any reconciliation free slots with no waitlist advance. Real.

Design (planner discretion, called out): a reconciler Schedule (60 s) in the Scheduling worker, matching the hold-reaper and pending-starter pattern; it is a new workflow type (no patch needed). Liveness is decided by `describe()` on `booking-{id}`: RUNNING is skipped, a not-found or any closed status means the workflow is gone, and a Temporal outage skips the whole step (never fail a booking because the control plane is unreachable). Ordering for a lost booking is void billing first, then fail the appointment and release the hold in ONE database transaction: if the void cannot be done the appointment stays pending and the next run retries, so the pair converges without a new marker column; billing voids for appointments the existing reaper already failed are covered by a lookback sweep (24 h) that writes an idempotent `billing_void_checked` history note, the only marker needed. No-show: billing `no_refund` first (Scheduling is allowed that transition), then `mark_no_show`; either failure leaves the appointment confirmed and the next run repeats both idempotently. Manual no-show marking by staff is not part of this plan.

Output: reconciler activities, workflow, Schedule and wiring; the reaper's waitlist offer; repository selectors; proofs including a recorded history.
</objective>
