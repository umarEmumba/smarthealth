<decisions>
## Implementation Decisions

### Must fix (Week 2 deliverables)
- **M1 Appointment state machine.** Add `checked_in`, `completed`, `no_show` states in Scheduling. Check-in moves the appointment into `checked_in`. Check-in is limited to a time window around the slot. Cancel and reschedule must be rejected once the appointment is `checked_in` or `completed` (today they rebook the slot and issue a refund).
- **M2 Provider schedule-change propagation.** Editing or deactivating an availability template, or deactivating a provider, must withdraw affected future slots (no longer bookable) via a new schedule-change workflow, and flag already-booked affected appointments.

### Should fix (reliability)
- **S3 Failures after commit.** Saga compensations must check the appointment's current state (never compensate or void billing on a `confirmed` booking). Audit-write failures after `confirm` become non-fatal, or move to an outbox.
- **S4 Stuck states.** Add a reconciler covering: `pending` appointments whose workflow died (they block the slot forever); waitlist entries stuck in `matched`; visit billing marked "skipped" that is never retried. Billing must keep retrying rather than skip.
- **S5 Waitlist.** A freed slot must be offered to the waitlist again if a direct booker takes it and then fails.
- **S6 Validation.** Booking a slot in the past must be rejected.
- **S7 Notification order.** "Booking confirmed" notification must be requested only after `confirm` succeeds. Update the README, which currently states the opposite.

### Carry-over from Week 1
- **C1** `/refresh` must check the token denylist and rotate the refresh token, so tokens stop working after logout.
- **C2** bcrypt hashing/verification must not run on the event loop (offload to a thread/executor).
- **C3** Email uniqueness must be case-insensitive (normalization and/or unique index on lower(email), with a migration that handles existing rows).
- **C4** Provider role can view its own appointments; patient can view its own profile.
- **C5** Patient, provider and clinic list endpoints are paginated.

### Missing deliverables
- **D1** Add quantified non-functional requirements to the PRD (target throughput, latency, availability).
- **D2** Add a load test. Measuring against the NFRs is expected to be finished in Phase 3 observability work; this phase delivers the NFR targets and the runnable load test.

### Claude's Discretion
- Plan split, wave ordering, and which service owns each change.
- Reconciler mechanism (Temporal Schedule vs sweeper, matching the existing hold-reaper / pending-starter pattern).
- Outbox vs non-fatal audit for S3 (must stay consistent with Phase 3's planned outbox/Kafka work).
- Load-test tool (e.g. k6 or Locust) and NFR numbers (justify against stated scale: tens of thousands of booking requests).
- Migration strategy for new states and the case-insensitive email index.

</decisions>
