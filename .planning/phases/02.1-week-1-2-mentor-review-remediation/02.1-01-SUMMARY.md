# Phase 02.1 Plan 01: Appointment State Machine Summary

**Scheduling now has `checked_in`, `completed` and `no_show` appointment states that hold their slot at the database level (widened CHECK, active-slot unique index and patient-overlap EXCLUDE in migration `scheduling_0004`), reached only through row-locked, DB-clock-correct transitions that Visit drives with a service token, and cancel/reschedule are refused for them at the API, the repository and the workflow activities.**

## Accomplishments

- **State machine (M1).** `pending -> confirmed -> checked_in -> completed`, `confirmed -> no_show`, `confirmed -> cancelled`, `pending -> failed`. `AppointmentStatus.ACTIVE` now lists every slot-holding status (pending, confirmed, checked_in, completed, no_show); `COMMITTED` (confirmed, checked_in, completed, no_show) is ready for plan 02.1-07's compensation guards.
- **Database guarantees.** `scheduling_0004` rebuilds `ck_appointments_status_valid`, `uq_appointments_active_slot` and `ex_appointments_patient_no_overlap` with widened predicates (supersets, so existing rows cannot violate them). `models.py` builds the same predicates from the enum, and `alembic check` is clean. A raw UPDATE of a cancelled twin into `completed` while a checked-in appointment holds the slot is rejected by the index, so the guarantee does not depend on application code.
- **Transitions.** `check_in_appointment` locks the row and computes `too_early` / `too_late` from `now()` in the same SELECT, then applies a conditional UPDATE and writes one history row; `complete_appointment` and `mark_no_show` follow the same shape; `list_no_show_candidates` serves the future sweep.
- **Routes.** `POST /internal/appointments/{id}/check-in` and `/complete` use `require_internal_caller(audience="scheduling", allowed_services={"visit"})` with no user roles. Outcomes map to 200 / 404 (identical) / 409 (`appointment not confirmed`, `check-in window not open`, `check-in window closed`, `appointment not checked in`). One audit entry (`appointment.check_in` / `appointment.complete`, actor `service:visit`, field names only, dedupe key per appointment and action) is written only when the change applied.
- **Refusals.** Public cancel and reschedule return 409 with `appointment already checked in`, `appointment already completed` or `appointment was a no-show`. The cancel and swap repository functions and the `NotCancellable` / `SwapRejected` activities already refused non-confirmed rows; tests now prove it for the three new states, including the race where state changes after the API check.
