## Pattern Assignments

### Per-service `app.py` (all 6 services + gateway)

**Analog:** `services/identity/app.py`

**Imports pattern** (lines 1-27):
```python
from contextlib import asynccontextmanager
from typing import AsyncIterator

from fastapi import FastAPI
from prometheus_fastapi_instrumentator import Instrumentator

from libs.audit.mongo_indexes import ensure_audit_indexes
from libs.observability.logging import configure_logging
from libs.observability.otel import setup_tracing
from services.identity.api.auth import router as auth_router
from smarthealth.db import get_mongo_client
```
Adapt import paths per service package (`services.organization.api.clinics`, etc.); each service's `libs.db` import moves to the new parameterized `libs/db/postgres.py` (see below).

**Lifespan + factory pattern** (lines 29-57):
```python
@asynccontextmanager
async def lifespan(app: FastAPI) -> AsyncIterator[None]:
    configure_logging()
    await ensure_audit_indexes(get_mongo_client())
    yield


def create_app() -> FastAPI:
    app = FastAPI(title="SmartHealth Identity Service", lifespan=lifespan)
    app.include_router(auth_router)
    ...
    setup_tracing(app)                       # pass service_name=<own> — see Shared Patterns
    Instrumentator().instrument(app).expose(app)
    return app


app = create_app()
```
Every new service's `app.py` keeps this exact shape: `title=` changes per service, `setup_tracing(app, service_name="smarthealth-<service>")` (see `libs/observability/otel.py:58` — `service_name` param already exists), and the router list is trimmed to only the routers that service owns. The Gateway's `app.py` differs only in that it has no `ensure_audit_indexes` call (no Mongo audit writes at the gateway tier) and instead wires `services/gateway/routing.py`'s proxy routes.

### Per-service CRUD router (Organization/Provider/Patient services)

**Analog:** `services/identity/api/departments.py` (full file read — every CRUD router in the monolith follows this exact shape: create/list/patch/deactivate, each wrapped in a `write_audit` call and a structlog `log.info` call)

**Imports pattern** (lines 19-36):
```python
from fastapi import APIRouter, Depends, HTTPException, status
from pydantic import BaseModel, Field
from pymongo import AsyncMongoClient
from sqlalchemy.ext.asyncio import AsyncSession

from libs.audit.writer import write_audit
from libs.observability.logging import get_logger
from services.identity.domain.enums import Role
from services.identity.security.current_user import AuthenticatedUser
from services.identity.security.rbac import require_role
from smarthealth.db import get_db, get_mongo
```

**Core CRUD + audit pattern** (lines 65-101, `create_department`):
```python
@router.post("", response_model=DepartmentOut, status_code=status.HTTP_201_CREATED)
async def create_department(
    clinic_id: uuid.UUID,
    payload: DepartmentCreate,
    user: AuthenticatedUser = Depends(require_role(Role.ADMIN)),
    db: AsyncSession = Depends(get_db),
    mongo: AsyncMongoClient = Depends(get_mongo),
) -> DepartmentOut:
    department = await org_repo.create_department(db, clinic_id=clinic_id, name=payload.name)
    if department is None:
        await write_audit(mongo, actor_id=user.sub, actor_role=user.role.value,
                           action="department.create", entity_type="department",
                           entity_id="unknown", clinic_id=str(clinic_id), outcome="failure")
        raise HTTPException(status_code=status.HTTP_404_NOT_FOUND, detail="clinic not found")
    await write_audit(mongo, actor_id=user.sub, actor_role=user.role.value,
                       action="department.create", entity_type="department",
                       entity_id=str(department.id), clinic_id=str(clinic_id), outcome="success")
    return _to_out(department)
```
**Every new-service router (Provider's `providers.py`, `availability.py`; Patient's `patients.py`) keeps this exact create/list/patch/deactivate + write_audit + log.info shape.** The only new addition per D-05: before the repository call, insert a synchronous validation call via `libs/service_client.py` for any cross-service FK field (e.g. Provider's `create_provider` calls `validate_department()` before `people_repo.create_provider(...)`), mapping `ReferencedResourceInvalid` → 422 and `UpstreamServiceUnavailable` → 503 (see RESEARCH.md Pattern 2).

**Error handling pattern** (lines 75-88, `404` on missing parent + audited failure): same shape reused for every cross-service 422 case — write a `outcome="failure"` audit record before raising the HTTPException.

### Per-service repository (Organization/Provider/Patient)

**Analog:** `services/identity/repository/org_repo.py` (full file read)

**Core pattern — scoped CRUD + soft-delete idempotency** (lines 24-84, `create_clinic`/`get_clinic`/`update_clinic`/`deactivate_clinic`):
```python
async def deactivate_clinic(db: AsyncSession, clinic_id: uuid.UUID) -> Clinic | None:
    clinic = await get_clinic(db, clinic_id)
    if clinic is None:
        return None
    if clinic.is_active:
        clinic.is_active = False
        clinic.deactivated_at = datetime.now(dt_timezone.utc)
        await db.commit()
        await db.refresh(clinic)
    return clinic
```
Deactivating an already-inactive row is a no-op success (returns unchanged), never an error — this idempotent-soft-delete shape must be preserved verbatim in every split-out repository (Organization keeps clinics/departments; Provider gets the provider/specialty/availability half of `people_repo.py`; Patient gets the patient half).

**Cross-service FK note (D-05):** `get_department` (lines 125-137) is the existing id-only lookup already used internally for the provider→department→clinic chain resolution — this becomes the basis for the new `/internal/departments/{id}` endpoint, but per RESEARCH.md Pitfall 5, that endpoint MUST add an explicit `is_active` check (the existing `get_department()` function does not filter on `is_active` — it was designed for internal chain-resolution only, not as a security/integrity boundary). Do not reuse it unmodified as the `/internal/` handler's only check.

### Per-service ORM models (`repository/models.py`)

**Analog:** `services/identity/repository/models.py` (full file read)

**Reusable column helper + per-service `Base`** (lines 52-69):
```python
from smarthealth.db import Base    # becomes: from libs.db.postgres import Base per-service

def _uuid_pk() -> Mapped[uuid.UUID]:
    return mapped_column(PG_UUID(as_uuid=True), primary_key=True,
                          server_default=text("gen_random_uuid()"))
```
**Critical change per RESEARCH.md's Anti-Patterns section:** each service must declare its OWN `class Base(DeclarativeBase)` (not the shared one) — copy the `Clinic`/`Department` classes' column shape (lines 72-121) verbatim into Organization's models, but do not import `smarthealth.db.Base`. Cross-service FKs become plain UUID columns with no `ForeignKey(...)` (e.g. `Provider.department_id` in Provider's own `models.py` loses its `ForeignKey("departments.id")` and becomes `mapped_column(PG_UUID(as_uuid=True), nullable=False)` — see D-01/D-05).

**Scheduling skeleton — `ProviderSlot`** (lines 309-352): moves verbatim into `services/scheduling/repository/models.py`, with `provider_id`'s `ForeignKey("providers.id")` removed (plain UUID, per D-03) and the `ExcludeConstraint`/`btree_gist` requirement kept exactly as-is.

### JWT signing/verification split (`libs/auth/`)

**Analog:** `libs/auth/jwt.py` (full file read) — the payload-shape and `algorithms=` explicit-allowlist conventions must survive the RS256 split unchanged.

**Signing half (Identity-only)** — keep `create_access_token`/`create_refresh_token`'s exact payload shape (lines 42-75), only swap `jwt.encode(payload, settings.jwt_secret, algorithm=settings.jwt_algorithm)` for `jwt.encode(payload, private_key_pem, algorithm="RS256", headers={"kid": ...})` per RESEARCH.md Pattern 1.

**Verification half (every service)** — keep `decode_token`'s `TokenError` exception and explicit-`algorithms=` pinning discipline (lines 78-103):
```python
try:
    claims = jwt.decode(token, jwks_key_dict, algorithms=["RS256"])
except JWTError as exc:
    raise TokenError(f"invalid token: {exc}") from exc
if claims.get("type") != expected_type:
    raise TokenError(...)
```
Never drop the explicit `algorithms=` allowlist (V6/alg-confusion note in the original docstring, lines 11-16) — this is a locked security invariant, not a style choice.

### `smarthealth/db.py` → `libs/db/postgres.py` (parameterized)

**Analog:** `smarthealth/db.py` (full file, 144 lines)

**Loop-aware singleton pattern** (lines 43-73) is the exact mechanism to preserve — only parameterize by an explicit `database_url: str` argument instead of reading the single global `settings.database_url`:
```python
def get_engine(database_url: str) -> AsyncEngine:
    global _engine, _engine_loop, _session_factory
    current_loop = asyncio.get_running_loop()
    if _engine is None or _engine_loop is not current_loop:
        _engine = create_async_engine(database_url, pool_pre_ping=True)
        _engine_loop = current_loop
        _session_factory = async_sessionmaker(bind=_engine, expire_on_commit=False)
    return _engine
```
Each service's own `config.py`/`db.py` module wraps this shared helper, calling `get_engine(settings.database_url)` with its own per-service `Settings.database_url` field. The Mongo singleton block (lines 114-144) is reused unchanged as shared infra (D-02 keeps one shared Mongo audit sink across services).

## Shared Patterns

### Structured logging + audit write (apply to every mutating router in every service)
**Source:** `libs/audit/writer.py` (full file, 80 lines), used identically from `services/identity/api/departments.py`
```python
await write_audit(
    mongo,
    actor_id=user.sub,
    actor_role=user.role.value,
    action="<entity>.<verb>",       # dot-namespaced
    entity_type="<entity>",
    entity_id=str(entity.id),
    clinic_id=str(clinic_id),
    outcome="success",               # or "failure"
    changed_fields=list(payload.model_fields_set),  # PATCH only — field NAMES, never PHI values
)
```
Call signature stays stable per D-02 so Phase 3 can swap internals for a Kafka producer without touching callers — do not modify this function's signature in this phase.

### OTel tracing setup (apply to every service's `app.py`)
**Source:** `libs/observability/otel.py` (full file, 85 lines) — already accepts a `service_name` parameter
```python
setup_tracing(app, service_name="smarthealth-<service-name>")
```
Add `opentelemetry-instrumentation-httpx`'s `HTTPXClientInstrumentor().instrument()` call once per process (Gateway + every service that makes internal `httpx` calls) so D-05 validation calls and gateway proxy calls propagate trace context automatically (RESEARCH.md "Don't Hand-Roll" — never hand-write `traceparent` headers).

### RBAC + token verification (apply to every protected route in every service)
**Source:** `services/identity/security/rbac.py` (`require_role`) + `services/identity/security/current_user.py` (`get_current_user`) — moved to `libs/`, JWKS-based per Pattern 1 above. Every service applies this locally (SC3 "defence in depth") — never delegate verification to a synchronous call to Identity per request (RESEARCH.md Pitfall 1, the single most-flagged anti-pattern for this phase).

### Synchronous cross-service reference validation (D-05) — new shared utility
**Source:** RESEARCH.md Pattern 2 (`libs/service_client.py`) — no prior in-repo analog since Phase 1 was single-process; apply to every writing service for every cross-service FK listed in D-05 (`users.clinic_id`, `patients.clinic_id`, `patients.user_id`, `providers.user_id`, `providers.department_id`, `availability_templates.department_id`).
```python
class ReferencedResourceInvalid(Exception): ...   # -> 422
class UpstreamServiceUnavailable(Exception): ...  # -> 503

@retry(retry=retry_if_exception_type(httpx.TransportError), stop=stop_after_attempt(3),
       wait=wait_exponential(multiplier=0.1, max=1.0))
async def _get(client, url, *, bearer_token): ...
```
Forward the caller's own bearer token on the internal call (service-to-service auth default) so the callee re-applies its own RBAC/clinic scope.

### Docker Compose service block (apply to every new container)
**Source:** `infra/docker-compose.yml`'s existing `api:` service block (lines 193-214) and `postgres`/`mongo`/`redis` healthcheck conventions (lines 10-57) — every new service container gets the same `env_file: .env`, `depends_on: <db>: condition: service_healthy`, and its own `${<SERVICE>_HOST_PORT}` published only for the gateway (per D-07/internal-only isolation, other services should NOT publish host ports once the gateway is the sole ingress).
