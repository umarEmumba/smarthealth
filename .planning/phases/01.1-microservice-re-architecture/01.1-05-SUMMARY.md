# Phase 01.1 Plan 05: Cross-service reference validation, service tokens and Identity user lookup Summary

**One shared, retry-bounded, trace-propagating client (`libs/service_client.py`) now enforces D-05 on Identity's own `users.clinic_id` on both the admin path (forwarded admin JWT) and the anonymous path (60-second Identity service token): 422 for a missing or inactive clinic, 503 when Organization cannot answer cleanly, and no row written either way. Identity also publishes a minimal `GET /internal/users/{id}` for the Patient and Provider account-link checks.**

## Accomplishments

- **Reference client (Task 1).** `lookup_reference` sends one GET per attempt with `outgoing_headers({"authorization": "Bearer ..."})`, inside `tenacity.AsyncRetrying` (retry only on `httpx.TransportError`, 3 attempts, `wait_exponential(multiplier=0.1, max=1.0)`, `reraise=True`). A transport error that survives the retries becomes `UpstreamServiceUnavailable`; 404 returns None; any other status, or a 200 whose body is not JSON or not an object, logs and becomes `UpstreamServiceUnavailable`. `require_active_reference` adds the 422 cases (missing, `is_active` false). The module contains no write-method call at all (acceptance check: neither `post(` nor `.put(` appears in its source).
- **Admin path (Task 1).** `create_staff_user` takes the internal http client and, when `clinic_id` is set, validates it with `admin.raw_token` before the duplicate check and insert. Shared helper `_validate_clinic_or_refuse` writes the `user.create` failure audit (entity_id "unknown") and raises 422 with `reference_error_detail(exc)` or 503 "organization service unavailable".
- **Service tokens (Task 2).** `create_service_token` signs `sub=service:<name>`, `type=service`, `jti`, `iat`, `exp = now + service_token_expire_seconds` (default 60) with the same RS256 key and kid as access tokens. `require_internal_caller` now decodes with `INTERNAL_CALLER_TYPES`; a service token must have a `sub` beginning `service:` (else 401), is denylist-checked like any token, and yields `InternalCaller(kind="service", role=None, clinic_id=None)`. `get_current_user` was not touched, so every public route still rejects service tokens.
- **Anonymous path (Task 2).** `register` validates `clinic_id` with `create_service_token("identity")`; same 422/503 and failure audit (actor anonymous). No clinic_id means no cross-service call.
- **User lookup (Task 2).** `services/identity/api/internal.py`: `UserRef(id, role, clinic_id)`, `GET /internal/users/{user_id}` for ADMIN and FRONT_DESK (plus service callers), 404 `{"detail": "not found"}` when the user is missing or `clinic_scope_permits` is false, log event `internal.user_lookup` with ids and outcome only, `include_in_schema=False`, mounted in `app.py`.
- **Harness (Task 1).** `degraded_mesh(*excluded, event_hooks=None)` builds a mesh where the named services refuse connections, installs it on every app for the block and restores the previous client; `request_recorder` returns a `RequestRecorder(requests, event_hooks)` NamedTuple (with a `paths(prefix)` helper) whose hook is appended to the live mesh client.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Deprecated Starlette constant in the new 422 path**
- **Found during:** Task 1 GREEN (pytest printed `StarletteDeprecationWarning: 'HTTP_422_UNPROCESSABLE_ENTITY' is deprecated`)
- **Issue:** The first GREEN draft used `status.HTTP_422_UNPROCESSABLE_ENTITY`, which warns on the pinned FastAPI/Starlette.
- **Fix:** Raise with the literal `422` and a comment; fixed before the GREEN commit, so the warning never landed.
- **Files modified:** services/identity/api/auth.py
- **Commit:** 568afe9

### Implementation choices inside the plan text (not scope changes)

- **Excluded services are mounted, not omitted.** The plan says `degraded_mesh` mounts every app except the excluded ones. An unmounted `http://organization:8000` would make httpx attempt a real DNS lookup, which is slow and environment-dependent, so each excluded host is mounted to `_UnreachableTransport`, which raises `httpx.ConnectError`. The app is still absent from the mesh; the failure is just deterministic and offline.
- **`request_recorder` appends its hook to the live mesh client** (`mesh.event_hooks["request"]`) instead of building a second mesh, and also exposes the `event_hooks` dict so `degraded_mesh(..., event_hooks=...)` can record too.
- **Reference check precedes the duplicate-email check on both paths**, as the plan specifies for the admin path and applied identically to `register`. Side effect: an unverifiable clinic_id yields 422/503 before the 409, so a bad clinic_id cannot be used to learn whether an email is registered.
- **Test counts exceed the plan minimums:** client unit tests 26 (min 9), service-token plus internal-users 26 (min 12), clinic reference 5 (min 5). Extras cover timeouts, malformed bodies, revoked and refresh tokens, user-subject service tokens, gateway non-routing and the log-content check.
- **File scope:** every file touched is in the plan's `files_modified` list.

**Total deviations:** 1 auto-fixed (Rule 1, caught pre-commit). **Impact:** none on scope; the choices above tighten determinism and coverage.
