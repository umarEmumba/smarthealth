## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Plan's HS256 forgery recipe cannot work**
- **Found during:** Task 2
- **Issue:** The plan prescribes `jose.jwt.encode(claims, public_pem, algorithm="HS256", ...)`. python-jose refuses to HMAC with a PEM key (documented in the 01.1-01 summary), so the test could not even build the token.
- **Fix:** `test_symmetric_algorithm_forgery_rejected` builds the token by hand (HS256 header with Identity's kid, `hmac` over the public PEM) and asserts 401 on `/api/admin/ping`. Same intent, attacker-realistic construction.
- **Files modified:** tests/identity/test_auth.py
- **Commit:** bce465f

**2. [Rule 3 - Blocking] Acceptance regex conflicts with plan-mandated negative assertion**
- **Found during:** Task 2 acceptance gate
- **Issue:** The criterion forbids the strings `jwt_secret` / `jwt_algorithm` anywhere in tests/identity and tests/libs, but the plan also requires asserting those fields are absent. Plan 01.1-01's `tests/libs/test_shared_settings.py` already tripped it (a test name and an assertion).
- **Fix:** Negative assertions now use a semantic predicate (no settings field name contains `secret` or `algorithm`), which is stricter than naming two fields; renamed `test_shared_settings_has_no_database_url_or_jwt_secret` to `..._or_shared_signing_secret`. This touches `tests/libs/test_shared_settings.py`, which the plan's `files_modified` does not list.
- **Files modified:** tests/libs/test_config.py, tests/libs/test_shared_settings.py
- **Commit:** bce465f

**3. [Rule 2 - Missing Critical] Must-have audit edges had no test in the plan's task list**
- **Found during:** Task 2
- **Issue:** The must-haves for the IAM-04 ordering edge (server-side UTC timestamp) and adjacency edge (failure then success stay two documents) named no test.
- **Fix:** Added `test_audit_timestamp_is_server_side_utc_and_ordered` and `test_failed_then_successful_attempt_produce_two_distinct_documents`; also added `test_duplicate_registration_creates_exactly_one_account` (idempotency edge) and `test_concurrent_duplicate_staff_creation_yields_one_account` (T-01.1-09 on the second route) to the lifecycle suite.
- **Files modified:** tests/identity/test_audit.py, tests/identity/test_account_lifecycle.py
- **Commits:** 33cb9a6, bce465f
