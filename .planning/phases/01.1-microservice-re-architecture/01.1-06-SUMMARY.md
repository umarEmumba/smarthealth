## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical functionality] Duplicate account link raised an unhandled unique violation**
- **Found during:** Task 2 RED (the duplicate-link test surfaced `asyncpg.exceptions.UniqueViolationError` through the app instead of a response)
- **Issue:** `patients.user_id` is unique (one profile per account), and the Phase 1 code had no handling for a second create with the same `user_id`, which would be an HTTP 500 and, with D-05 validation now accepting any real account, is an easy path to trigger. A concurrent pair of creates would hit the same constraint.
- **Fix:** `create_patient` catches `IntegrityError`, rolls the session back, and (when a `user_id` was supplied) writes the failure audit and answers 409 "account is already linked to a patient profile"; an `IntegrityError` with no `user_id` is re-raised because nothing else a validated create can violate is expected. The database constraint stays the arbiter, so no application lock was added.
- **Files modified:** services/patient/api/patients.py, tests/patient/test_patient_references.py
- **Verification:** `test_second_profile_for_same_account_is_409_and_not_written` (one row for the account after both attempts)
- **Committed in:** 4b479c5 (test in 9ae9157)

### Implementation choices inside the plan text (not scope changes)

- **`HARNESS_SERVICES` edit placed in the GREEN commit** rather than RED, for the reason given under TDD Gate Compliance.
- **Named unique constraint.** The plan says "unique constraint on user_id"; it is declared as `uq_patients_user_id` in both the model (`__table_args__`) and the migration so the two agree and autogenerate stays quiet.
- **Reference check is one helper.** Both reference checks and their 422/503 mapping live in `_validate_references_or_refuse`, called once from `create_patient`, instead of two inline blocks across the two tasks; behaviour is as specified.
- **Test counts exceed the plan minimums:** 12 reference tests (min 9), 3 tracer tests (min 3), 13 relocated tests.
- **File scope:** every file touched is in the plan's `files_modified` list.

**Total deviations:** 1 auto-fixed (Rule 2). **Impact:** closes a 500 on a reachable input; no scope creep.
