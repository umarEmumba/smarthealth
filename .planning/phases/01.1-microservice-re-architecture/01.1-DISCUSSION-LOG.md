## Cross-service integrity

### Reference validation

| Option | Description | Selected |
|--------|-------------|----------|
| Sync REST call to owner at write time (Recommended) | 404/inactive → 422; fails if owner down | ✓ |
| Local replica fed by events | Requires Kafka + outbox now | |
| Hybrid: sync call + Redis cache | Stale-cache edge cases | |

### Deactivating referenced entities

| Option | Description | Selected |
|--------|-------------|----------|
| Allow; references stay, new writes blocked (Recommended) | No cascade, no distributed transaction | ✓ |
| Block deactivation while references exist | Bidirectional coupling | |
| Cascade deactivation | Needs events/orchestration | |

## Claude's Discretion

- API gateway implementation (default: thin FastAPI gateway; JWT verified at every service)
- Repo & data layout (default: monorepo `services/<name>/`, installable infra-only `libs/`, one database per service on a single Postgres container)
- Service-to-service auth (default: forward caller JWT; internal endpoints not gateway-routed)
- RS256/JWKS key handling for local dev, internal-call timeouts/retries, migration strategy

## Deferred Ideas

- Dedicated Audit service consuming a Kafka audit topic (Phase 3)
- Event-fed local replicas of reference data (Phase 3)
- Cascading deactivation via events/orchestration (not planned)
