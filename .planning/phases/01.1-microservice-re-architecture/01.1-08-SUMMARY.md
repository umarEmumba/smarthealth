## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `get_internal_http_client` crashed in every real container**
- **Found during:** Task 2, first real-stack smoke run (`GET /api/admin/ping` returned 500).
- **Issue:** the dependency was a plain `def`, so FastAPI ran it in a worker thread where `asyncio.get_running_loop()` raises `RuntimeError: no running event loop`. Every request that depends on it with no injected client failed. The in-process harness always injects a client, so no earlier test could see it.
- **Fix:** made it `async def` and `await` it in the gateway; added `tests/libs/test_http_default_client.py`, which failed before the fix and passes after.
- **Files modified:** libs/http.py, services/gateway/app.py, tests/libs/test_http_default_client.py
- **Commit:** `2863364`

**2. [Rule 3 - Blocking] Postgres `max_connections` exhausted by the multi-service stack**
- **Found during:** full in-process run with the stack up (`TooManyConnectionsError`).
- **Issue:** Temporal alone holds about 40 connections at idle and each application worker keeps its own SQLAlchemy pool, so the stock limit of 100 is exceeded in a normal local run.
- **Fix:** `command: ["postgres", "-c", "max_connections=300"]` on the postgres service. The container was recreated; the named volume and all databases were untouched (verified by listing databases afterwards). Full suite then passed: 348 passed.
- **Files modified:** infra/docker-compose.yml
- **Commit:** `5962bdd`

**3. [Plan adjustment] Compose shared blocks via YAML anchors, e2e skip behaviour**
- The plan describes per-service blocks; the shared environment, healthcheck and depends_on are anchors (`x-app-env`, `x-app-healthcheck`, `x-app-depends-on`) and each service adds only its own database URL. Resolved config is what the plan specified.
- `tests/e2e/test_gateway_smoke.py` skips when no gateway is reachable (so the existing `pytest tests/...` commands stay green without a stack) and fails instead when `SMARTHEALTH_E2E_REQUIRE_STACK=1`.
- The plan's Jaeger/Prometheus human-check was executed through their HTTP APIs, not the UIs (see coverage D10).

**Total deviations:** 2 auto-fixed, 1 plan adjustment. No Rule 4 changes.
