<assumption_delta_decision>
Detector signal: `pluralization` on "No service connects to another service's database." — the phase turns ONE shared persistence identity (a single `DeclarativeBase`/`MetaData`, a single `DATABASE_URL`) and ONE shared trust anchor (a symmetric HS-family secret every process knew) into many.

- **Primary noun (generalized identity):** the *service-owned data store* — one database, one DB role, one `DeclarativeBase`, and one `<SERVICE>_DATABASE_URL` alias per service; and the *Identity-owned signing keypair* — an RSA private key only Identity loads, published to everyone else as a JWKS keyed by `kid`.
- **Decision: `promote`.** The per-service Base/DB and the Identity keypair become the only representations. The shared monolith `Base`, the bare `DATABASE_URL` setting and the shared JWT secret/algorithm settings are removed from every live code path, not kept alongside (keeping a bare `DATABASE_URL` alongside would silently point new services at the old shared database — RESEARCH Runtime State Inventory). The old monolith modules stay on disk only until plan 01.1-09 deletes them; nothing live imports them after this plan.
- **Invariant test (accepted):** plan 01.1-09 adds `tests/libs/test_service_isolation.py`, which goes red if any service metadata registers another service's table, any service imports another service's package, any settings class reads an unprefixed `DATABASE_URL`, or a service DB role can connect to another service's database.
</assumption_delta_decision>
