<objective>
Deliver the synchronous cross-service integrity mechanism (D-05) as one shared, retry-bounded, trace-propagating client, and apply it to Identity's own cross-service reference (`users.clinic_id` → Organization) on both the admin and the anonymous path. Add Identity's `/internal/users/{id}` lookup and the service-token type that the anonymous path needs, so Patient (01.1-06) and Provider (01.1-07) can validate `user_id` links (D-04) with the same client.

Purpose: This is the one place the split introduces genuinely new failure modes (owner unavailable, mixed auth contexts); proving the 422/503 contract on Identity first means Patient and Provider only reuse it.
Output: `libs/service_client.py`, service tokens, validated account creation, `/internal/users`, unit + integration tests, and a degraded-mesh harness helper for owner-unreachable tests.
</objective>
