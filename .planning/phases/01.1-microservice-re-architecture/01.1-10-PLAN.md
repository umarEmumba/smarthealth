Facts to state (all decided and built in plans 01.1-01..09):
- Services and databases: gateway (no DB), identity → identity_db (users), organization → organization_db (clinics, departments), provider → provider_db (providers, specialties, provider_specialties, availability_templates), patient → patient_db (patients, only PHI), scheduling → scheduling_db (provider_slots + ex_provider_slots_no_overlap). One Postgres container; role `<service>_svc` per database; PUBLIC connect revoked; created by the idempotent db-init job; the legacy `smarthealth` database is left untouched (non-destructive; an operator may drop it).
- Auth: RS256, kid `smarthealth-identity-1`, JWKS at `/.well-known/jwks.json`, every service verifies locally from a cached JWKS (300s TTL, 30s unknown-kid backoff), shared Redis denylist checked by every service, 60s service tokens for calls with no user context, private key delivered only to identity as a Compose secret.
- Gateway: thin FastAPI + httpx proxy, route table (/api/auth, /api/admin, /.well-known/jwks.json → identity; /api/clinics → organization; /api/providers → provider; /api/patients → patient), /internal/* and unsafe paths 404, hop-by-hop stripping, 503/504 mapping, per-IP fixed-window limits (auth 20/min, default 300/min) with deliberate fail-open + metric, no JWT verification and no aggregation at the edge.
- Integrity: synchronous GET to the owner's /internal endpoint at write time, forwarded JWT, 3 bounded retries on transport errors, missing/inactive → 422, owner down → 503, nothing written; no cascade on deactivation; reads return ids only; Kafka/outbox and event-fed local copies are Phase 3.
- Audit: shared libs/audit write_audit (unchanged signature) into one shared audit_log collection; dedicated Audit service is Phase 3.
- Observability: one connected trace across services via W3C traceparent (OTel propagator + httpx client spans), one Prometheus job per service.
- Behaviour change: provider under a missing department returns 422 (was 404) per D-05.
- Configuration variables: take the table from 01.1-09-SUMMARY.md ("Configuration hand-off" if present) or from `.env.example` / `infra/.env.example`.
