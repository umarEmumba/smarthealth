## TDD note

Task 2 is `tdd="true"` but pins guarantees that plans 01.1-01..08 already delivered, so a literal RED (failing before implementation) is impossible and a passing first run is expected. To avoid a vacuous suite the tests were mutation-checked instead: temporarily injected a service-to-service import, `JWT_SECRET` / `"HS256"` / `private_pem` names in `libs/`, and a libs-to-services import; the import, symmetric-config and key-locality tests went red (3 failed), the temporary files were removed and the suite returned to 12 passed. The role-isolation test also pins the refusal reason ("permission denied") so an unreachable Postgres cannot pass it. The metrics change was built with its tests alongside; the public-listener-404 test fails against the previous behaviour by construction (the old route answered 200 everywhere).

## Decisions Made

- Live-code scanning (via `ast`) for the symmetric-JWT invariant instead of a raw text regex, because two docstrings legitimately say "HS256" to explain its rejection.
- Metrics listener split by ASGI `server` scope rather than a token or header: no new secret, nothing client-controlled, and the plan's files and Compose publishing rules stay unchanged.
- Body-size cap deferred rather than half-built (see Deferred Issues).

- **Found during:** Task 2, first run (5 failures). Isolation was working; the test caught the wrong type.
