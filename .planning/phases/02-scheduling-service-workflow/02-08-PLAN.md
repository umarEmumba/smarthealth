<objective>
Deliver cancel and reschedule as Temporal workflows on the Scheduling queue (SCHED-05, SCHED-06, BILL-02; D-13, D-14; Planning-Time Decision "409 on cancel/reschedule while pending").

Purpose: Cancellation must release the slot and drive the refund state; rescheduling must be atomic (reserve-then-swap in one local transaction, never cancel-then-rebook). Both reuse the hold, idempotent-activity and audit patterns from the booking saga, and both decide time-dependent policy in the API request so workflow history stays deterministic (research A11).

Output: `CancelWorkflow`, `RescheduleWorkflow`, `AppointmentChangeActivities`, repository steps, cancel/reschedule endpoints, committed histories for replay, tests.
</objective>
