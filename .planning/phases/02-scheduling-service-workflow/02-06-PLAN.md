<objective>
Add Temporal to the stack and deliver the booking saga end to end (SCHED-01, SCHED-02, SCHED-04 at the HTTP layer, BILL-01; D-05, D-06, D-07, D-09, D-11).

Purpose: This is the phase's core reliability path: the API accepts a booking in one local transaction and returns 202; a durable Temporal workflow on the Scheduling task queue validates, holds the slot, runs the billing pre-check, records the notification intent and confirms. Compensations are registered before each step and run as forward transitions (D-09). Saga order follows D-09 (billing before notification) per the Planning-Time Decision; this deviates from the SCHED-02 text, which lists notification first, because the notification is best-effort and should fire only after the last fallible step. "Prevent conflicts" maps to the reserve step's database constraints (uq_appointments_active_slot, ex_appointments_patient_no_overlap).

Deviation called out: `temporalio==1.34.0` instead of the CLAUDE.md pin 1.32.0 — every research probe (start policies, Schedules, worker-crash recovery, compensation order, converter round-trips) ran on 1.34.0 against the Compose server 1.29.7, and CLAUDE.md's own rule is "pin the exact version you test against". 1.32.0 is the fallback if the human checkpoint rejects 1.34.0. The package legitimacy gate flagged temporalio SUS (latest-release recency, missing registry download stats), so Task 1 is a blocking human verification before install.

Output: the pinned SDK, `libs/temporal.py`, `libs/temporal_policies.py`, workflow contracts, `BookingWorkflow`, `SchedulingActivities`, the worker entrypoint, `/api/appointments` routes, Temporal test fixtures and tests.
</objective>
