<objective>
Close the internal-auth gap every later Phase 2 plan depends on (research G1, G2, G5; D-06 per the Planning-Time Decision "Identity client-credentials endpoint issuing one token per audience (`aud`, required `exp`)").

Purpose: Temporal activities outlive the HTTP request and carry no user context (D-06), so Scheduling, Visit and Billing workers need a way to authenticate to Patient, Provider, Organization, Billing and Scheduling internal routes. Today only Identity can sign a service token, the token has no audience, and any service token passes any internal route. This plan adds a client-credentials mint on Identity, per-audience tokens with required `exp`, verifier-side audience and allowed-caller checks, a caching token provider, a write-capable internal client for activities, and an idempotent audit writer (activities retry, so "an audit entry per step" must not duplicate).

Output: Identity `POST /internal/service-tokens`; `libs/auth/service_tokens.py`; `libs/internal_client.py`; widened `decode_token` / `require_internal_caller`; `write_audit(dedupe_key=)`; per-service secret generation script; tests.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Spoofing | POST /internal/service-tokens | high | mitigate | Per-service secret compared with `hmac.compare_digest`; identical 401 for unknown client / wrong secret / missing file; route under `/internal` (never in the gateway table); audience restricted by `SERVICE_TOKEN_AUDIENCES` (403 otherwise) |
| T-02-02 | Elevation of Privilege | require_internal_caller | high | mitigate | Service tokens must carry `aud` equal to the receiving service (401 otherwise) and the caller must be in the route's `allowed_services` (403 otherwise); covered by the Task 2 rejection matrix |
