<objective>
Deliver the waitlist (SCHED-07) per D-12 and research Pattern 7, and wire it to the two places a booked slot is freed: cancel (D-13) and the old slot of a reschedule (D-14).

Purpose: A freed slot must advance the waitlist to the next appropriate patient. The match is FIFO by creation time among entries for the same provider whose window contains the slot, and the chosen entry is auto-booked through the normal booking saga so idempotency, holds, compensation and audit are all reused (D-12). The claim is a row lock with `SKIP LOCKED`, so concurrent frees cannot pick the same entry. CancelWorkflow and RescheduleWorkflow have recorded histories (02-08), so starting the advance is added behind `workflow.patched` and proven by replay (D-19).

Discretion choices (called out per CONTEXT): the advance id is `waitlist-advance-{source_workflow_id}` rather than research's `waitlist-advance-{appointment_id}-{n}`, so a cancel and a reschedule of the same appointment never collide; only cancel and reschedule start an advance (a hold released by compensation or the reaper was never a booked slot, and joining a waitlist while a matching slot is open does not auto-book; both limits are documented); the claim activity creates the appointment via `accept_booking` with key `waitlist-{appointment_id}` (id from `workflow.uuid4()`, deterministic per iteration), caller `entry.created_by`, and `workflow_started_at` set in the same transaction so the 02-07 pending-starter never races the child start.

Output: migration `scheduling_0003`, `WaitlistEntry` model and repository, `/api/waitlist` routes, `WaitlistAdvanceWorkflow` + `WaitlistActivities`, patched cancel/reschedule workflows, new recorded histories, tests.
</objective>
