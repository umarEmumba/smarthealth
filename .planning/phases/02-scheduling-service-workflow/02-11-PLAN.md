<objective>
Make visit completion trigger downstream work without blocking (VISIT-04) and drive billing to `finalized` (BILL-02), per D-16 and research Pattern 8.

Purpose: The completion transition must never wait on Billing or any other downstream system. The transition commits with `downstream_started_at IS NULL`; after the commit the API starts `visit-completed-{visit_id}` (deterministic ID, start-once) and sets the marker. A sweeper (once at worker start, then on a Temporal Schedule) starts the workflow for any completed visit whose marker is still NULL, closing the commit-then-start gap. The workflow fans out to three idempotent activities: billing finalize, follow-up intent, analytics intent. The intents are Phase 2 stubs (log line plus audit entry, D-11); Phase 3's transactional outbox, Kafka and Celery replace both the sweeper and the stubs (the dashboard in 02-12 says so).

Design choices within discretion: the three branches run concurrently with `asyncio.gather` inside the workflow (deterministic), each wrapped so its failure is recorded in the result instead of failing the workflow; billing finalize uses the long `COMPENSATION_ACTIVITY` budget because completion is already committed and billing must catch up, while the intents use `NOTIFY_ACTIVITY` (best-effort). Run-on-start lives in the visit worker (it has the Temporal client), not in the API lifespan, so an API boot never blocks on Temporal.

Output: Visit workflow contracts, `VisitCompletedWorkflow`, `VisitDownstreamSweeperWorkflow`, `VisitActivities`, `services/visit/downstream.py`, `ensure_visit_schedules`, the visit worker entrypoint, the completion hook in the API, the `visit_worker` test fixture, tests and a recorded history.
</objective>
